# Phase 02：游戏流程与玩家入场

## 目标

实现可测试的顶层状态机和 1–4 人座位加入流程，形成“主菜单 → 玩家加入 → 热身”的首个全触控闭环。

## Codex 执行任务

1. 实现 `GameFlowController` 与显式状态类型：Boot、MainMenu、PlayerJoin、Warmup 等；状态转换必须可审计。
2. 实现 `PlayerManager`、`PlayerState`、`PlayerSnapshot`，每个座位拥有稳定 ID、方向、颜色、图标和初始 50 金币。
3. 创建四个座位面板：下侧玩家 1/2 正向，上侧玩家 3/4 整体旋转 180°。
4. 每个座位只提供大尺寸“点击加入”按钮；加入后显示金币、玩家标识与准备状态。
5. 创建“开始/继续”按钮：至少 1 人加入才可用；不得以定时器自动替玩家确认。
6. 定义玩家加入、离开、快照更新事件；View 不直接修改玩家数据。
7. 为非法状态转换、重复加入、零玩家继续、1–4 人组合编写测试。
8. 加入状态超时的安全恢复，但恢复动作必须回到可操作界面，不得自动开始下注。

## 职责核查

- `GameFlowController` 不保存金币。
- `PlayerManager` 不切换场景或控制 UI。
- Button 只发送命令；按钮禁用态来自只读状态。
- UI 上的退出、返回均为 Button，不使用 Escape。

## 验收

- 1、2、3、4 人均能从主菜单进入并到达 Warmup。
- 两名玩家同时点击不同座位不会串位或重复加入。
- 同一座位连点只创建一个玩家。
- 0 人时继续按钮不可用并有清晰提示。
- 返回主菜单会明确清理会话；无残留透明遮罩阻断触控。

## 退出条件

状态转换和玩家测试通过；四座 UI 朝向、触控区域与并发点击完成编辑器手工验证。达到后方可执行 Phase 03。
