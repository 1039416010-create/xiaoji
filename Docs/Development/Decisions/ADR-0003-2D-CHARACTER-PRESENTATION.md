# ADR-0003：正式角色表现改为 2D 混合动画

- 状态：已接受
- 日期：2026-09-20

## 背景

Phase 11 的程序化三维模型完成了骨架、LOD、导出和 Unity 导入验证，但主要形体、
面部和羽毛语言与已确认的角色细化图仍有明显差距。继续精修 13 套三维模型会把大量
投入用于重建已经在二维概念图中成立的角色形象。

## 决定

正式角色表现改为二维混合动画：侧视分层 Sprite 与 2D 骨骼负责待机、热身、跑步、
冲刺和减速；轮廓变化较大的摔倒、恢复、掉头、干扰、庆祝和失败允许使用角色专属
替换图或逐帧关键姿势。既有三维资产归档，不作为最终 Release 表现资产。

比赛规则不变：`ChickenController.NormalizedProgress` 仍是赛道位置唯一真相，动画
不得包含推动名次的位移；`RaceDirector` 的受控随机、结算、换鸡、金币与触控规则均
保持不变。

## 后果

- 13 只鸡必须制作统一规格的侧视分层母版、头像、表情和 11 个动作槽。
- Run 与 Sprint 切换保持步态归一化相位；一次性动作从自身开头播放。
- 生成式动作表只作为姿势和风格参考，需经过透明边缘清理、分层和 Unity 实机验证后
  才能进入发布资源。
- `Chicken3DStage` 在 2D 五鸡同屏舞台完成前继续作为开发降级显示，之后由 2D 舞台替换。

## 未采用方案

- 继续批量生成三维模型：工程指标可通过，但不能保证概念图还原。
- 每个动作全部使用高帧数逐帧动画：十三只角色的维护量过高，且状态衔接难以统一。
- 整张角色图片平移：无法表达腿部、翅膀、尾羽、表情和配饰的个性动作。
