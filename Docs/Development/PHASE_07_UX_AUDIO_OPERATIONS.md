# Phase 07：完整 UI、音频与展项运维

## 目标

把已有系统打磨为适合 180×90 cm 桌面投影的公共展项：双侧可读、反馈明确、全程可触控、可恢复、可维护。

## Codex 执行任务

1. 完成主菜单：开始游戏、设置、退出游戏，全部为可见 Button。
2. 完成玩家加入、热身、下注、倒计时、比赛、结算、换鸡、GameOver 全状态 UI。
3. 对四个玩家区进行朝向、色彩+图标双编码、余额与锁定状态一致性检查。
4. 统一按钮视觉状态：Normal、Pressed、Disabled、Confirmed；不依赖 Hover。
5. 所有关键按钮增加防抖，但保持不同 Pointer ID 的独立响应。
6. 设置页提供音量、现场亮度/视觉强度、最大局数等允许项目；保存本机设置，不保存个人数据。
7. 建立 AudioMixer 分组和 BGM/SFX；倒计时、按钮、冲线、结算有清晰但不过载的声音反馈。
8. 建立触控确认弹窗：退出、返回主菜单、重开；弹窗必须同时适配两侧阅读或使用图形化表达。
9. 建立展项诊断页：通过可见按钮进入，显示触点、分辨率、版本、设备状态、种子与最近错误。
10. 建立日志轮转、异常恢复和空闲回首页策略；空闲操作不得中断正在进行的比赛。
11. 检查文字本地化入口，不在脚本中散落 UI 文案。

## UI 布局标准

- Canvas 基准 1920×960，中央比赛区优先，玩家操作区位于上下长边。
- 上侧玩家 3/4 的整个面板旋转 180°；面板内部不逐个反转造成坐标混乱。
- 必要按钮按最终物理尺寸不小于约 25 mm，并留出防误触间隔。
- 终点、赛道号、冠军、金币使用图标辅助，中央避免长段单向文字。
- 所有遮罩、CanvasGroup 和动画结束后恢复正确 Raycast 状态。

## 验收

- 不使用键盘，从启动到退出可完成全部路径。
- 桌面两侧玩家无需倒看自己的操作文案。
- 四人同时操作各自区域，无跨区选择、双扣或全局锁触控。
- 中断任一 UI 动画后不会留下不可点击遮罩。
- 应用失焦/恢复、分辨率变化和场景重载后回到安全状态。
- 日志长时间运行有大小上限，且能定位最近一局种子和结算。

## 退出条件

主菜单至 GameOver 的全触控闭环通过；UI、音频、诊断和异常恢复均有手工记录。达到后方可执行 Phase 08。
