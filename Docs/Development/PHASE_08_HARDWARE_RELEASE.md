# Phase 08：红外触控实机、压力测试与发布

## 目标

在目标 Windows 主机、投影设备和 Windows HID 红外多点触控硬件上完成校准、稳定性、性能与发布验收，产出可部署版本和现场操作说明。

## Codex 执行任务

1. 固定 Unity 版本、包锁文件、URP 质量档和 Windows x64 构建配置。
2. 生成 Development 候选版，开启触点可视化、种子与详细日志；不得加入键盘诊断快捷键。
3. 在 180×90 cm 桌面完成投影 2:1 映射、方向、边缘安全区和触控坐标校准。
4. 记录 HID 设备型号、驱动、Windows 缩放、投影分辨率、刷新率与触点上限。
5. 进行 1–4 人流程、4/10 点并发、边缘按钮、快速重复触摸、手掌/误触场景测试。
6. 执行至少 500 局自动 soak test 和 60 分钟实机运行；收集帧时间、GC、内存、日志大小和异常。
7. 测试应用失焦、投影重连、触控设备重连、非正常关闭后重启；必须回到安全入口。
8. 生成 Release Build，关闭冗余诊断但保留有限日志和 UI 诊断入口策略。
9. 创建发布清单、配置备份、回滚包和现场开关机/校准/故障恢复说明。
10. 对最终包执行一次从冷启动到两种 GameOver 的全流程验收。

## 性能与稳定性目标

目标数值应根据最终硬件写入验收记录；最低原则如下：

- 目标刷新率下无持续掉帧或明显触控延迟。
- 正常比赛帧内不得产生可观的持续 GC Alloc。
- 500 局无卡局、无重复结算、无错误冠军、无持续内存爬升。
- 设备断连不会让应用永久不可操作；无法热恢复时给出明确的屏幕内恢复按钮。
- 日志容量受控，磁盘空间不足时优雅降级而不是崩溃。

## 最终验收清单

- [ ] Windows x64 Release 在目标机器冷启动成功。
- [ ] 1920×960 逻辑画面完整投满 180×90 cm 有效区域且无拉伸。
- [ ] 上下两侧 UI 朝向正确，所有必要按钮在安全触控区内。
- [ ] 1–4 人与并发触控通过。
- [ ] 锁定前无赛果，锁定后赛果唯一且可复现。
- [ ] 冠军留场、四鸡替换、金币继承和两种 GameOver 通过。
- [ ] 完全不使用键盘也能设置、游玩、重开、返回与退出。
- [ ] 现场维护人员能根据文档完成启动、校准、查看日志和恢复。
- [ ] 发布包、符号/日志策略、配置和回滚版本均已归档。

## 退出条件

所有最终验收项有证据并签字/记录；Release 包与现场手册齐全；不存在会导致卡局、错误账务或无法退出的已知严重问题。项目方可标记为首版可部署。
