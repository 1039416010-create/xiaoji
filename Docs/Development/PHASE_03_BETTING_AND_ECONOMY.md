# Phase 03：选鸡、下注与金币

## 目标

实现每名玩家独立的选鸡与 1/5/10 金币下注面板，确保全员确认后下注锁定，且锁定前绝不生成比赛结果。

## Codex 执行任务

1. 实现 `BettingManager`、`BetState`、不可变下注快照和明确错误码。
2. 玩家先通过五个鸡按钮选择目标，再通过 1/5/10 三个按钮选择金额，最后点击“确认下注”。
3. 确认时原子校验：玩家有效、鸡有效、金额允许、余额足够、当前为 Betting、尚未锁定。
4. 采用“确认即扣本金”的统一账务策略；记录余额流水。若产品决定改为结算时扣款，必须先更新根规范和测试。
5. 玩家确认后冻结其所有选择按钮，展示目标、金额和“已锁定”。不得提供撤销。
6. 所有可下注玩家锁定后，只发布一次 `AllBetsLocked`，再由流程进入倒计时准备。
7. 金币为 0 的玩家显示旁观状态，不计入等待锁定集合。
8. 编写并发/重复点击、余额边界、非法金额、重复确认和全员锁定顺序测试。

## 安全与公平断言

- `BettingManager` 不引用 `RaceDirector` 的具体实现，只发布锁定完成事件或返回命令结果。
- 在 `AllBetsLocked` 之前，测试必须能断言 RacePlan 不存在。
- 任何日志和 UI 在锁定前都不得出现冠军字段。

## 验收

- 每个玩家区域只能修改自己的下注。
- 余额 4 时只有 1 金币可选；余额 0 时不能下注。
- 双击确认只扣一次金币、只产生一份下注。
- 1–4 人的全员锁定判定准确，破产旁观者不阻塞开赛。
- 返回或重置会清除本局下注，但不会无意清除已定义的会话金币。

## 退出条件

下注和账务测试全部通过；全员锁定事件恰好一次；比赛系统仍未提前生成结果。达到后方可执行 Phase 04。
