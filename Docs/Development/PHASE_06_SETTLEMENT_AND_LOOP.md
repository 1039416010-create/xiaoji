# Phase 06：结算、换鸡与连续局

## 目标

完成下注结算、胜负表现、冠军留场、四名败者替换、金币跨局继承，并实现两种 GameOver 条件。

## Codex 执行任务

1. 实现幂等 `SettlementService`，以局号/比赛 ID 防止重复结算。
2. 按总返还规则结算：下注锁定已扣本金；押中返还 `2 × stake`，未押中不返还。
3. 为每名玩家生成结算明细：目标鸡、下注、本局输赢、返还、结算后余额。
4. 播放冠军庆祝；失败四鸡进入幽默、非血腥的“咖喱鸡排饭”结果画面。表现内容必须适合公共展项。
5. 实现 `RosterService`：保留冠军稳定 ID/实例，替换其余四只，保证新阵容数量为 5 且 ID 唯一。
6. 下一局清空局级下注与 RacePlan，保留玩家加入状态和金币。
7. 局号递增后检查：所有已加入玩家余额为 0，或局号达到 MaxRounds；满足则进入 GameOver。
8. GameOver 展示结束原因、最终金币和排名，并提供“再来一局”“返回主菜单”按钮。
9. 编写结算幂等、多人同押、无人押中、单人破产、全员破产、最大局数与换鸡测试。

## 边界规则

- 多名玩家可押同一只鸡并分别获奖。
- 玩家余额只能由统一账务接口修改，结果不能出现负数。
- 单个玩家破产后作为旁观者保留在 UI；不阻塞其他玩家下一局下注。
- 若配置库不足以替换四只不重复鸡，必须在开局前由配置验证器报错，不能比赛中静默复用。
- 结算动画即使跳过或异常，也不得跳过账务或重复账务；业务结算与表现播放分离。

## 验收示例

- 玩家有 50，押 10 后余额 40；押中返还 20，结算后 60；押错则保持 40。
- 同一 `RaceResult` 提交两次，第二次不改变任何余额。
- 冠军在下一局仍保持身份，四名败者全部被新成员取代。
- 最后一名有金币的玩家输光后进入 Bankrupt GameOver。
- 达到最大局数时即使仍有金币，也进入 MaxRounds GameOver。

## 退出条件

至少完整自动运行 100 局无负余额、重复派彩、错误阵容或卡局；两种结束条件均通过。达到后方可执行 Phase 07。
