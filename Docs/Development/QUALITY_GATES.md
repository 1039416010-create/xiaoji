# 共用质量门禁与验收记录模板

## 每阶段自动检查

- Unity 项目可在指定 Unity 6.3 LTS 版本打开，无自动升级提示。
- Runtime、Editor、EditMode Tests、PlayMode Tests 程序集无编译错误。
- 新增或修改的业务规则有自动化测试。
- 场景、Prefab、ScriptableObject 无 Missing Script、Missing Reference。
- Console 无未解释的 Error 或 Exception。
- 未引入游客必须使用的键盘或鼠标专属交互。
- 无影响赛果的非确定性运行时随机调用。
- 没有将用户已有无关修改覆盖或格式化。

## 最终功能矩阵

| 场景 | 必须结果 |
|---|---|
| 1–4 人加入 | 每个座位只加入一次，至少 1 人可继续 |
| 多人同时点击 | 各自按钮独立响应，无串位与吞触摸 |
| 非法下注 | 非 1/5/10、余额不足、重复确认均被拒绝 |
| 全员锁定前 | 不存在本局冠军或 RacePlan |
| 全员锁定后 | 只生成一份已验证、不可变的 RacePlan |
| 比赛 | 恰好一只鸡有效冲线，且在硬超时内结束 |
| 结算重入 | 同一局不会重复扣款或返奖 |
| 下一局 | 冠军仍在，其余四鸡换新，金币保持 |
| 单人破产 | 该玩家旁观，其他玩家继续 |
| 全员破产 | GameOver，结束原因为 Bankrupt |
| 最大局数 | GameOver，结束原因为 MaxRounds |
| 异常恢复 | 回到可操作状态，不留透明遮罩或死按钮 |
| UI 退出 | 无键盘操作即可安全返回/退出 |

## 统计与压力建议

- 对至少 10,000 个种子执行纯逻辑比赛计划测试。
- 连续自动游玩至少 500 局，检查内存增长、重复结算、无效阵容与卡局。
- 1、2、3、4 人各完成至少 20 次完整现场流程。
- 实机同时触摸 4 个玩家区；硬件支持时增加到 10 个并发触点。
- 在目标设备跑 60 分钟 soak test；记录平均/高分位帧时间、GC 峰值、异常与日志大小。
