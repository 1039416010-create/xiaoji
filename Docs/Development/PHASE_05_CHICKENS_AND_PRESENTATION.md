# Phase 05：鸡角色、动画与比赛表现

## 目标

把预生成的 `RacePlan` 稳定呈现为五只风格不同的小鸡比赛，支持热身、冲刺、停顿、摔跤、掉头、终点前停住和邻道干扰，同时不让表现层改变赛果。

## Codex 执行任务

1. 创建 `ChickenDefinition` 与至少 5 个可替换的角色定义；外形、名字、性格标签和动画能力配置化，不写固定胜率。
2. 实现 `ChickenController`，只消费 `ChickenRacePlan` 并用程序控制归一化赛道位置。
3. 建立 Animator 状态：Idle、Warmup、Run、Sprint、Stop、Fall、Recover、Turn、Interfere、Celebrate、Lose。
4. 关闭用于推进位置的 Root Motion；动画只表现，逻辑轨迹是唯一位置真相。
5. 实现行为调度与可中断恢复。缺失动画时使用安全 fallback，不得卡住比赛。
6. 干扰事件只在相邻赛道播放成对动画/VFX；不通过真实碰撞改变剧本。
7. 加入对象池或稳定实例管理，避免每局高频 Instantiate/Destroy。
8. 增加取消、重置、强制安全姿态和超时完成接口。
9. 使用 Unity Profiler 检查五鸡同时运动、动画、VFX 时的 GC 和帧时间。
10. 编写 PlayMode 测试：各行为进入/退出、重置、缺动画降级、剧本结束位置。

## 动画约束

- Animator 参数集中定义并使用哈希，禁止散落字符串。
- 动画事件可以发出纯表现提示，不能扣金币、判定冠军或切换顶层状态。
- 鸡的 Collider 仅用于需要的表现查询，不能参与终点胜负判定。
- 掉头时允许视觉朝左和短距离回退，但最终轨迹仍严格服从计划。
- 摄像机和赛道必须确保五只鸡全程可见；不做要求玩家追踪视角的交互。

## 验收

- 五只鸡可同时从左向右运行，外观和动作有明显差异。
- 每个要求的随机行为至少有一个受计划驱动的演示用例。
- 低帧率模拟下冠军不变、事件顺序不乱、最终能结算。
- 连续播放 100 局无鸡残留、错道、动画锁死或持续内存增长。
- 关闭任一非关键动画/VFX 资源时仍可安全完成比赛。

## 退出条件

所有表现均由已锁定计划驱动；位置和赛果不受物理、动画或帧率影响；PlayMode 与性能基线通过。达到后方可执行 Phase 06。
