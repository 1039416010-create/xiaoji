# Phase 04：受控随机比赛核心

## 目标

实现 `RaceDirector` 的预生成比赛剧本：全员锁定后才产生结果，同一种子可复现，每局恰好一个冠军，所有鸡在限定时间内完成安全播放。

## 数据模型

建议至少包含：

- `RaceSeed`：可序列化种子。
- `RacePlan`：版本、配置哈希、局号、种子、冠军 ID、总时长、五份 `ChickenRacePlan`。
- `ChickenRacePlan`：赛道、关键帧/运动分段、行为事件和预期结束位置。
- `RaceSegment`：起止时间、起止进度、插值类型、朝向。
- `RaceEvent`：类型、起止时间、参数、可选邻道目标。
- `RaceResult`：冠军、冲线时间、完成原因和剧本标识。

## Codex 执行任务

1. 把随机源封装为可注入接口，不在业务各处直接使用 UnityEngine.Random。
2. `RaceDirector` 仅响应已锁定下注后的开始命令，生成一次不可变 `RacePlan`。
3. 先等概率选择冠军，再为五只鸡生成满足约束的路径与事件；生成器不得读取下注目标或金额。
4. 建立 `RacePlanValidator`：五赛道齐全、ID 唯一、时间单调、进度合法、唯一冠军、总时长不超限。
5. 生成失败时在限定次数内重试；仍失败则使用经过验证的保底模板并记录错误。
6. 用归一化赛道进度 `[0,1]` 描述逻辑位置，再由赛道映射为世界坐标。
7. 实现倒计时 3、2、1、GO；倒计时只播放已经锁定的计划。
8. 比赛播放结束由计划中的唯一冲线事件触发 `RaceResult`；硬超时可强制依据计划结束。
9. 编写至少 10,000 种子的纯逻辑测试，以及同种子复现测试。

## 公平性测试

- 注入两组完全不同的下注快照但使用同一种子与阵容，生成的冠军和核心计划必须相同。
- `GenerateRacePlan` 在 Betting 未锁定时必须拒绝调用。
- 运行时修改 UI、帧率或时间缩放不得改变已确定的冠军。

## 验收

- 每份有效计划包含 5 只鸡且恰好一只有效冲线。
- 所有事件留在各自赛道安全边界内，邻道干扰只表现、不越权决定名次。
- 相同版本、配置和种子结果一致。
- 发生播放异常或鸡未到位时仍能在硬超时进入下一状态。
- 日志可用种子、配置哈希和阵容重建该局。

## 退出条件

批量种子、锁定时序、公平性、唯一冠军和硬超时测试通过。达到后方可执行 Phase 05。
